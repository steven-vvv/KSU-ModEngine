# v0.1 架构与接口约定

第一版交付可运行的 Linux 开发预览：宿主派生自有 fixture 进程，Lua 5.4 / QuickJS-ng Runner 在独立进程中通过受控 IPC 搜索、读取、修改 fixture 的一页匿名内存。生产 Android 目标接入、绘制、perf/eBPF、MCP 延后，不能将开发预览当作可安装的 Android 模块。

## 信任与资源边界

- 宿主读取一次源码，检查清单，计算全文 SHA-256；显式批准相同摘要后将该份源码发给 Runner。Runner 无权声明宿主 capability。
- 第一版仅授予 `mem.read` / `mem.write_heap`；已知但未实现的权限在授权时拒绝，未知清单字段或权限在解析时拒绝。
- fixture 模式只允许访问宿主自己派生的子进程的一页匿名私有非执行映射。不能通过参数把任意 PID 或伪造 UID 传入此路径。
- Android 目标后续必须由宿主从 Package Manager 解析 package/UID、保护包列表、多用户 appId、进程启动时间与 pidfd，并逐次复验；单靠 UID >= 10000 不成立。
- 源码上限 48 KiB；IPC 载荷上限 64 KiB；单次内存传输上限 16 KiB；结果最多 1024 条。扫描为精确小端 i32；先实现有测试的标量路径。
- VM 堆默认 64 MiB，执行预算默认 2000ms；宿主另设独立墙钟截止时间并终止超时 Runner。最多 10000 条请求和 64 KiB 日志。
- strict 沙箱要求网络/挂载 namespace、空根、清空附加组并降权、capability 清除、no_new_privs、rlimit 与 seccomp，任一步失败终止。`development` 必须由用户显式指定，只保证 no_new_privs / rlimit / FD 清理 / seccomp；允许留存当前 UID，不能用于第三方脚本或任意应用目标。绝不自动降级。
- 单线程 Runner 完成动态加载和 VM 初始化之后才安装 seccomp，然后执行源码。封禁文件打开、联网、进程创建、exec、ptrace、kill 与可执行 mmap/mprotect。IPC FD 固定为 3，清理其他继承 FD。不存在可由脚本调用的 shell、动态模块或文件接口。

## ipc-proto（冻结）

所有消息 `serde` 编解码为 MessagePack，16-byte little-endian 帧头：magic[4] = KSME，version:u8=1，kind:u8（1=Bootstrap,2=Request,3=Response），flags:u16=0，request_id:u32，payload_len:u32。拒绝未知 kind/version/flags、过大或截断数据包、尾随字节与 ancillary data；地址传输为 u64。

```rust
pub struct MemoryRange {
    pub start: u64, pub end: u64,
    pub readable: bool, pub writable: bool, pub executable: bool,
    pub private: bool, pub name: Option<String>,
}
pub struct Bootstrap {
    pub source: String, pub script_name: String,
    pub timeout_ms: u64, pub memory_limit_bytes: u64,
}
pub enum Request {
    SandboxReady { mode: String },
    Log { message: String },
    GetRanges,
    ReadMemory { address: u64, len: u32 },
    WriteMemory { address: u64, data: Vec<u8> },
    ScanI32 { value: i32 },
    RefineI32 { value: i32 },
    GetResults { limit: u32 },
    WriteResultsI32 { value: i32 },
    Finished { error: Option<String> },
}
pub enum Response {
    Ok,
    Ranges { ranges: Vec<MemoryRange> },
    Bytes { data: Vec<u8> },
    ScanCount { count: u32 },
    Results { addresses: Vec<u64> },
    Error { code: String, message: String },
}
pub enum Message { Bootstrap(Bootstrap), Request(Request), Response(Response) }
pub struct Packet { pub request_id: u32, pub message: Message }
pub struct SeqPacket; // implements AsRawFd
impl SeqPacket {
    pub fn pair() -> std::io::Result<(Self, Self)>;
    pub fn from_owned_fd(fd: std::os::fd::OwnedFd) -> Self;
    pub fn send(&self, packet: &Packet) -> Result<(), ProtocolError>;
    pub fn recv(&self) -> Result<Option<Packet>, ProtocolError>;
    pub fn set_recv_timeout(&self, timeout: std::time::Duration) -> std::io::Result<()>;
}
```

`Packet` 编解码另提供纯函数以供畸形输入测试。请求 ID 从 1 递增；bootstrap ID 为 0；响应必须对应请求 ID。宿主在 `SandboxReady` 前拒绝内存操作。`Finished` 也需要响应，然后 Runner 退出；成功取决于无协议错误、成功 Finished 和进程零退出码。

## engine-core（冻结）

清单模块提供 `Manifest::parse(&str) -> Result<Manifest>`、`source_hash(&[u8]) -> String`、`Authorization::approve(&Manifest, source: &[u8], approved_hash: &str) -> Result<Authorization>`。清单公开 `id/name/version/matches/grants/connect`；grant 为 `BTreeSet<Capability>`，枚举至少包含 `MemRead/MemWriteHeap`，其余计划中已知 grant 可解析但不能批准。Authorization 提供 `grants()`。

内存模块提供 `TargetIdentity::capture(pid:i32)`、`verify()`、`parse_maps(&str)`，以及 `MemorySession::for_fixture(identity, range:MemoryRange, authorization:Authorization)`。fixture session 必须校验目标为本机当前 UID 的直接子进程、range 对应非执行匿名私有映射（包括 [anon:*]），每次访问重读映射和验证 identity。仅允许全部落在此 range 的请求。

`MemorySession` 提供 `maps(&mut self)`、`read(&mut self,address:u64,len:usize)`、`write(&mut self,address:u64,data:&[u8]) -> Result<usize>`、`scan_i32(&mut self,value:i32) -> Result<usize>`、`refine_i32(&mut self,value:i32) -> Result<usize>`、`results(&self,limit:usize) -> Result<Vec<u64>>`、`edit_all_i32(&mut self,value:i32) -> Result<usize>`。map/read/scan/results 需要 MemRead；write/edit 需要 MemWriteHeap。读写短传输必须显式报告，写入不可承诺事务回滚。fixture 写边界额外要求 readable + writable + private + !executable，禁止文件映射与特殊映射。

## sandbox-common（冻结）

```rust
pub enum SandboxMode { Strict, Development }
pub struct SandboxConfig {
    pub mode: SandboxMode, pub ipc_fd: i32,
    pub memory_limit_bytes: u64, pub cpu_time_seconds: u64,
    pub empty_root: Option<std::path::PathBuf>,
}
pub struct SandboxReport {
    pub mode: SandboxMode, pub namespaces: bool,
    pub dropped_privileges: bool, pub seccomp: bool,
}
pub fn enter(config: &SandboxConfig) -> Result<SandboxReport, SandboxError>;
```

strict 空根由宿主创建并以 `--empty-root PATH` 传入 Runner；退出后宿主清理。不要求普通开发主机拥有 root；strict 不可用必须准确报错。沙箱测试只能在独立测试子进程内安装过滤器，不允许影响 cargo/宿主或其他进程。

## Runner 与宿主

Runner CLI：`--ipc-fd 3 --sandbox strict|development [--empty-root PATH]`。bootstrap 在过滤器安装前接收；VM 初始化、安装桥接 API 后执行 `enter`；发送 `SandboxReady`，等待响应，然后执行源码。错误通过 Finished 返回；源码只允许文本。

JS：`engine.scanI32(value)`, `engine.refineI32(value)`, `engine.results(limit)`（地址为十六进制字符串）, `engine.readI32(address)`, `engine.writeI32(address,value)`, `engine.editAll(value)`, `engine.log(text)`；`console.log` 支持。Lua 提供同名 engine API（地址为 64 位整数）和基础 `gg.TYPE_DWORD/searchNumber/getResults/editAll/setValues`；只承诺 DWORD 子集，不承诺完整 GG/Frida 兼容。宿主的错误必须成为脚本异常，不能吞掉。

宿主 CLI 首轮：`doctor [--json]`、`inspect-script PATH [--json]`、`run PATH --fixture --approve SHA256 [--development-sandbox] [--json]`。默认 strict；未批准、摘要变化、目标不匹配、未知权限、危险权限、缺失 Runner 一律失败。fixture 包名固定 `com.example.ksumod.fixture`，内存包含 1337，演示脚本修改为 7331。宿主派生 fixture-target 的内部子命令，fixture 只向父进程公布一页地址并等待控制管道关闭；宿主退出必须回收全部子进程。

WebUI 第一版为 KernelSU 风格的管理预览：粘贴脚本、展示清单/摘要/权限、生成明确 CLI 授权命令与运行说明。未完成 Android transport 前不冒充已经能安装/运行；所有脚本内容以 textContent 或等效方式展示，禁止 HTML 注入。

## 并行开发规则

各代理在独立 Git worktree 修改分配目录；不修改根 Cargo.toml、Cargo.lock 或其他代理目录。接口变更先通知主代理。主代理统一下载依赖、编译、集成与执行整套测试，Cargo jobs=2。代理可运行纯脚本静态检查，重型编译需协调。最终报告必须区分已测与未测。
